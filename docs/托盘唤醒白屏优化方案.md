# 托盘唤醒白屏优化方案

> 日期：2026-07-19
> 状态：已实施

## 背景

当前项目为了保持后台低资源占用，用户关闭主窗口后会销毁前端和 WebView2 实例，只保留 Rust 后台监听逻辑。该策略必须继续保留。

现象：从系统托盘唤醒主界面时，窗口会短暂出现白屏，然后才显示真实 UI。此前已经修复了窗口不可见问题，但短时间白屏仍存在。

核心判断：剩余白屏主要来自新 WebView2 实例创建后，HTML/CSS/Svelte 首屏挂载之前的短暂空档；也可能被前端启动时主题变量的清空和重设进一步放大。

## 不可破坏约束

- 关闭主窗口后必须继续销毁前端和 WebView2 实例。
- 后台常驻时仍以低内存 Rust 进程为主，不能通过常驻隐藏 WebView 来换取唤醒速度。
- 不使用屏幕外坐标隐藏窗口，避免再次污染窗口位置保存、多屏坐标和焦点行为。

## 推荐实施顺序

### 阶段一：先做主题与底色修正

目标：不改变窗口生命周期，只减少 WebView 首次绘制时露出的白底。

#### 1. 保留 `app.html` 的预置主题变量

当前 `src/app.html` 会在 head 脚本中根据 `localStorage.tracer-theme` 预置 CSS 变量和主题 class，这是正确方向。

需要调整 `src/routes/+layout.svelte`：

- 不要在 `onMount` 一开始删除 `app.html` 已设置的内联 CSS 变量。
- 首屏阶段先信任 `localStorage` 里的主题，让页面从第一帧就有稳定底色。
- 异步读取数据库 `theme` 后，如果数据库值存在并且与当前值不同，再调用 `applyTheme(theme)` 覆盖。
- 数据库读取失败时，不要强制切回 `system` 造成闪烁；应尽量保留 `app.html` 已应用的主题。

建议逻辑：

```ts
let currentTheme = localStorage.getItem('tracer-theme') || 'system';

onMount(async () => {
  applyTheme(currentTheme);

  try {
    const theme = await getConfigValue('theme');
    if (theme && theme !== currentTheme) {
      currentTheme = theme;
      applyTheme(currentTheme);
    }
  } catch (e) {
    console.error('加载主题配置失败:', e);
  }

  // 后续继续注册 theme-changed 和系统主题监听。
});
```

注意：示例只表达方向，实施时应保持现有事件监听和清理逻辑，不额外重构。

#### 2. 让最底层背景使用 `--color-bg`

当前 `src/app.css` 中 `body` 使用 `bg-surface`，浅色主题下通常是白色。WebView 在首屏还没挂载完整 UI 时，如果先画出 body，就会露出白底。

建议调整：

- `html, body` 使用 `background: var(--color-bg)`。
- 必要时让最外层容器 `.window-shell` 也使用 `background: var(--color-bg)`。
- 保持卡片、面板、列表等内容区域继续使用 `--color-surface`，不要大范围改视觉系统。

建议目标：

```css
html, body {
  background: var(--color-bg);
}

body {
  color: var(--color-text-primary);
}

.window-shell {
  background: var(--color-bg);
}
```

如果 Tailwind `@apply` 仍用于其他属性，避免顺手重写全局样式。

### 阶段二：如仍可见，再做隐藏创建 + 首帧 ready

目标：在不常驻 WebView 的前提下，让用户看不到 WebView2 空白初始化过程。

#### 1. Rust 创建窗口时先隐藏

修改 `src-tauri/src/lib.rs` 中 `show_main_window` 的新建窗口分支：

- 已存在窗口：维持当前 `show` / `unminimize` / `set_focus` 逻辑。
- 不存在窗口：使用 `WebviewWindowBuilder` 创建新窗口时先隐藏，设置主题匹配的原生背景色。
- 创建后仍调用 `restore_and_monitor_window_size`。
- 等前端通知 ready 后，再显示并聚焦。

注意：不要使用 `set_position(-32000, -32000)` 之类的屏幕外隐藏方案。

#### 2. 前端首帧完成后通知 Rust

新增一个 Tauri command，例如 `notify_frontend_ready`：

- 前端在 `+layout.svelte` 完成主题应用后，使用 `requestAnimationFrame` 等待至少一帧。
- 然后调用 `notifyFrontendReady()`。
- Rust 收到后显示 main 窗口、取消最小化并聚焦。

建议前端触发时机：

```ts
requestAnimationFrame(() => {
  requestAnimationFrame(() => {
    notifyFrontendReady().catch(console.error);
  });
});
```

双 `requestAnimationFrame` 的目的，是让 CSS 变量、主题 class 和 Svelte 初始布局有机会完成一次真实绘制。

#### 3. Rust 加兜底显示

为了避免前端异常导致窗口永远不可见，新建窗口后启动一个短兜底：

- 如果 800ms 内没有收到 ready，则直接显示窗口。
- 收到 ready 后应标记该窗口已显示，兜底不再重复操作。
- 这个状态应按窗口创建周期维护，不要做复杂全局状态。

建议兜底时长：`600ms` 到 `1000ms`，初始推荐 `800ms`。

## 验收标准

- 关闭主窗口后，WebView2 进程应消失，`tracer.exe` 内存回落到后台基线。
- 从托盘唤醒时，不再出现明显白底闪烁；浅色主题应显示接近 `#F0F0EC` 的背景，深色主题不应闪白。
- 连续执行 10 次“关闭窗口 → 托盘唤醒”，窗口位置、大小、焦点均正常。
- 主题分别验证：`system` 浅色、`system` 深色、`pure`、`dark`。
- 前端 ready 通知失败时，窗口仍能在兜底时间后显示，不会变成不可见窗口。

## 实施记录

- 已调整 `src/routes/+layout.svelte`：首屏先使用 `localStorage` 主题，数据库主题异步覆盖；前端首帧完成后通知 Rust。
- 已调整 `src/app.css`：最底层 `html, body` 背景使用 `--color-bg`，避免 WebView 初始绘制白底。
- 已调整 `src-tauri/src/lib.rs`：新建主窗口时先隐藏，收到 `notify_frontend_ready` 后显示；若前端 ready 失败，800ms 后兜底显示。
- 已调整 `src/lib/api/commands.ts`：增加 `notifyFrontendReady()` 调用封装。

## 不建议的方案

- 不建议常驻隐藏 WebView：会破坏后台低资源目标。
- 不建议创建到屏幕外再移动回来：容易污染 `window_pos`，并引入多屏和 DPI 问题。
- 不建议用固定延迟后显示窗口替代 ready 通知：不同机器 WebView2 初始化耗时不同，体验不稳定。
- 不建议大范围重构主题系统：本次目标只是消除唤醒白屏。
