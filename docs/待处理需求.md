## 🚀 启动与托盘唤醒性能优化

### 主窗口重建速度优化 (后续可选)

- **背景**：当前已解决托盘唤醒白屏问题，并保留关闭主窗口后销毁前端和 WebView2 实例的低后台占用策略。后续若继续优化，目标应是缩短“点击托盘 → 主窗口可交互”的体感时间，而不是让 WebView 常驻后台。

- **优先级 1：首屏数据延后加载**
  - 将窗口显示与首页数据加载解耦。
  - `+layout.svelte` 只负责主题、布局和 ready 通知。
  - 首页统计、排行榜、热力图、图标等数据在窗口显示后再加载。
  - 预期收益最大，风险相对可控。

- **优先级 2：评估进一步提前 `notifyFrontendReady`**
  - 当前 ready 通知在本地主题应用后的下一帧触发。
  - 可实验直接在 `applyTheme(currentTheme)` 后通知 Rust 显示窗口。
  - 风险是可能露出一帧未完成布局，需要和白屏/闪动表现一起实测。

- **优先级 3：优化 Rust 窗口创建参数**
  - 将窗口尺寸、位置读取前置到 `WebviewWindowBuilder` 构建参数阶段。
  - 减少窗口 build 后再调整尺寸/位置造成的等待或视觉抖动。
  - 涉及 Rust 窗口创建逻辑，改动前需跑 GitNexus impact analysis。

- **优先级 4：缓存主题到 Rust 侧**
  - 避免 `show_main_window()` 每次托盘唤醒都读取数据库来决定原生窗口背景色。
  - 设置主题时同步维护 Rust 内存缓存。
  - 预计收益较小，但可以简化唤醒路径。

- **优先级 5：前端代码拆包**
  - 当前构建存在较大的 JS chunk，后续可考虑对图表、非首屏页面或重组件做动态 import。
  - 目标是减少 WebView 冷启动时必须解析/执行的 JS。
  - 属于性能专项，建议在有明确性能基线后再做。
